# ADR-0012: The kiln-platform Application delivers every Go module's CRD

**Status:** Accepted, 2026-09-05. Supersedes [ADR-0008](0008-platform-app-delivers-the-tenantdatabase-crd.md).

## Context

ADR-0008 added `operator/config/crd/bases` to the `kiln-platform` Application so a fresh cluster has the `TenantDatabase` kind before anything emits or guards one. Phase 4 adds a second module with its own generated CRD, `CanaryRollout` in `delivery-controller/config/crd/bases`, and its controller Application (`kiln-delivery`, sync wave 2) cannot start its informers until that kind exists.

## Decision

ADR-0008 stands in every respect except that the `kiln-platform` source list now includes the CRD directory of every Go module that generates one:

| Application | Source | Drift policy |
|---|---|---|
| `crossplane`, `kyverno`, `istio-base`, `istiod` | Helm charts at pinned versions, rendered by ArgoCD | selfHeal, prune |
| `kiln-platform` | `operator/config/crd/bases`, `delivery-controller/config/crd/bases`, `gitops/compositions`, `gitops/policies` in this repo | selfHeal, prune |
| `kiln-scheduler`, `kiln-delivery` | `scheduler-plugin/config`, `delivery-controller/config/manager` in this repo | selfHeal, prune |
| `kiln-tenants` | `gitops/tenants` in this repo, recursive | no selfHeal, no prune |

Each module remains the owner of its CRD's content; Git delivery through the platform Application at sync wave 1 is the only way any of them reaches a cluster. Controllers that need a CRD run in a later wave.

## Consequences

- A cluster bootstrapped purely from `gitops/argocd` has every platform kind before any controller starts; the CI `platform-e2e` job proves it on a fresh kind cluster for both modules.
- A future module with a CRD adds one source line here, not a new delivery path.
- The delivery controller's ClusterRole is generated by controller-gen from RBAC markers into `delivery-controller/config/manager` and checked in CI like the CRD.

## Note on supersession scope

This ADR supersedes only ADR-0008's CRD source decision, the set of source paths the `kiln-platform` Application delivers, by extending it from the single operator CRD to the CRD directory of every Go module. Nothing else in ADR-0008 changes.

ADR-0008's own header claims it supersedes ADR-0007, which overstated its scope. ADR-0007's decision is the per-Application drift policy (selfHeal/prune per Application class); that decision stands independently and is unchanged by ADR-0008 or by this ADR. Both ADR-0008 and this one amend only the `kiln-platform` source list, layered on top of ADR-0007's drift-policy decision, which remains in force. ADR-0008 is not edited (ADRs are immutable); this note records the correct scope.
