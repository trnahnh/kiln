# ADR-0008: The kiln-platform Application also delivers the TenantDatabase CRD

**Status:** Accepted, 2026-09-05. Supersedes [ADR-0007](0007-argocd-bootstraps-the-platform-with-drift-policy-per-application.md).

## Context

ADR-0007 listed the `kiln-platform` Application with two sources, `gitops/compositions` and `gitops/policies`. The first CI run of the Phase 2 end-to-end test failed on a fresh cluster: nothing in Git installed the `TenantDatabase` CustomResourceDefinition, so Kyverno could not register a webhook rule for `tenantdatabases` and Crossplane could not compose one. Locally the CRD had been left behind by Phase 1's `make install`, which hid the gap. The CRD is generated by the operator module and lives at `operator/config/crd/bases`.

## Decision

ADR-0007 stands in every respect except the source list of `kiln-platform`, which is now:

| Application | Source | Drift policy |
|---|---|---|
| `crossplane`, `kyverno` | Helm charts at pinned versions, rendered by ArgoCD | selfHeal, prune |
| `kiln-platform` | `operator/config/crd/bases`, `gitops/compositions`, `gitops/policies` in this repo | selfHeal, prune |
| `kiln-tenants` | `gitops/tenants` in this repo, recursive | no selfHeal, no prune |

The operator module remains the owner of the CRD's content; Git delivery through the platform Application is the only way it reaches a cluster. The README bootstrap order is ArgoCD first, then `make run` for the operator.

## Consequences

- A cluster bootstrapped purely from `gitops/argocd` has every kind the composition emits and the policies guard before either is applied; the CI `platform-e2e` job proves it on a fresh kind cluster.
- `make install` is no longer part of the documented getting-started path; it stays in the operator Makefile for the envtest and integration workflows that run without ArgoCD.
- A CRD change is a commit under `operator/` and reaches clusters like any other platform change, self-healed if edited live.
